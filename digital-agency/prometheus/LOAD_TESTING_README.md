# Инструкция по нагрузочному тестированию Digital Agency

## Подготовка к тестированию

1. **Установка k6**:
   ```
   # Windows (через Chocolatey)
   choco install k6

   # Linux
   sudo apt-key adv --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
   echo "deb https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
   sudo apt-get update
   sudo apt-get install k6
   ```

2. **Проверка установки**:
   ```
   k6 version
   ```

3. **Запуск мониторинга**:
   - Убедитесь, что Prometheus и Grafana запущены:
     ```
     cd digital-agency/prometheus
     docker-compose up -d
     ```
   - Запустите серверы метрик для мониторинга:
     ```
     # В первом терминале
     cd digital-agency/prometheus
     node static-metrics.js

     # Во втором терминале
     cd digital-agency/prometheus
     node static-process-metrics.js
     ```

## Запуск нагрузочного тестирования

1. **Базовое тестирование**:
   ```
   cd digital-agency/prometheus
   k6 run load_test.js
   ```

2. **Тестирование с сохранением результатов**:
   ```
   k6 run --out json=results_week1.json load_test.js
   ```

3. **Тестирование с разными параметрами**:
   ```
   # 10 виртуальных пользователей на 5 минут
   k6 run --vus 10 --duration 5m load_test.js

   # 50 виртуальных пользователей на 10 минут
   k6 run --vus 50 --duration 10m load_test.js
   ```

## Мониторинг результатов

1. **Grafana Dashboard**:
   - Откройте http://localhost:3000 (логин: admin, пароль: admin)
   - Перейдите к дашборду "Digital Agency API Monitoring"

2. **Проверка метрик в Prometheus**:
   - Откройте http://localhost:9090
   - Проверьте доступность метрик:
     - api_response_time_ms
     - system_uptime_percent
     - api_request_errors_total
     - node_cpu_usage_percent

3. **Анализ логов**:
   - Проверьте логи в Kibana: http://localhost:5601
   - Исследуйте таблицу system_logs на наличие ошибок

## Анализ результатов

Сравните следующие метрики до и после нагрузочного тестирования:

1. **Производительность API**:
   - Среднее время ответа (должно быть < 250 мс)
   - 95-й процентиль времени ответа
   - Количество запросов в секунду

2. **Доступность и надежность**:
   - Процент доступности (целевое значение: 99.5%)
   - Количество ошибок API

3. **SLA метрики**:
   - Время преобразования запроса в проект (целевое значение: 92%)
   - Время ответа в чате (целевое значение: 98%)

4. **Использование ресурсов**:
   - Использование CPU (целевое значение: < 70%)
   - Использование памяти (целевое значение: < 60%)

## График тестирования

Рекомендуется проводить нагрузочное тестирование по следующему графику:

- **Ежедневное тестирование**: 15 минут с 30 виртуальными клиентами (~75 запросов/мин)
- **Еженедельное тестирование**: 1 час с 50 виртуальными клиентами (~125 запросов/мин)
- **Ежемесячное тестирование**: 4 часа с постепенным увеличением нагрузки от 10 до 100 виртуальных клиентов
